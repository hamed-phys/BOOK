# مشروع القراءة والمراجعة الجماعية

هذا مشروع **موقع ثابت** يعمل مباشرة على GitHub Pages. وظيفته عرض كتالوج الكتب، النسخة الحالية لكل كتاب، حالته، نسبة المراجعة، وسجل الإصدارات والتحديثات. ملفات PDF والتعليقات نفسها تبقى خارج GitHub، ويفضل وضعها على Google Drive.

## أين توجد الأشياء؟

- **GitHub**: ملفات الموقع، الأغلفة الصغيرة، `site.json`، `books.json`، `updates.json`، وسجل تغييرات المستودع.
- **Google Drive**: ملفات PDF التي يقرأها المراجعون والتعليقات المرتبطة بها.
- **تلقائيًا داخل الموقع**: عدد التحديثات، آخر تاريخ ظاهر، قائمة التخصصات، قائمة الحالات الموجودة، آخر 6 تحديثات، الفرز والبحث.
- **تحدّثه أنت يدويًا**: الإصدار الحالي، الحالة، نسبة المراجعة، وصف الكتاب، الرابط الحالي، `last_updated` عند تغيير بيانات الكتاب نفسها، وأحداث `updates.json`.

> الموقع لا يقرأ تعليقات Google Drive ولا يحسب التقدم منها.

## الملفات التي ستعدلها غالبًا

| ما الذي تريد تغييره؟ | الملف |
|---|---|
| اسم المشروع، المقدمة، وصف المشروع، رابط GitHub، رابط الموقع النهائي | `data/site.json` |
| إضافة كتاب أو تغيير بياناته الحالية | `data/books.json` |
| إضافة إصدار/تصحيح/تقدم/حالة تاريخية | `data/updates.json` |
| إضافة غلاف | `assets/covers/` |
| ألوان وتصميم عام | `assets/css/style.css` |

للمبتدئ: استخدم [`tools/update-helper.html`](tools/update-helper.html) بعد نشر الموقع. الشرح اليدوي موجود في [`HOW_TO_ADD_A_BOOK.md`](HOW_TO_ADD_A_BOOK.md) و[`HOW_TO_UPDATE_A_BOOK.md`](HOW_TO_UPDATE_A_BOOK.md). إعداد Drive في [`GOOGLE_DRIVE_SETUP.md`](GOOGLE_DRIVE_SETUP.md).

## أول تخصيص بعد فك ZIP

1. افتح `data/site.json` من GitHub وعدّل:
   - `title`
   - `intro`
   - `about`
   - `github_url` بعد إنشاء المستودع، أو اتركه فارغًا.
   - `site_url` بعد معرفة رابط GitHub Pages النهائي. يجب أن يكون رابطًا كاملًا وينتهي بـ `/`، مثل `https://USERNAME.github.io/book-review/`.
2. احذف السجلات التجريبية الثلاثة أو استبدلها بكتبك الحقيقية. السجلات التجريبية تحمل `"demo": true` وتظهر بوضوح على الموقع.
3. مرة واحدة عند تغيير اسم المشروع، حدّث النصوص الثابتة في `<head>` داخل `index.html` و`book.html`: `<title>` و`meta description` ووسوم Open Graph. `site.json` يحدّث واجهة الصفحة بعد تشغيل JavaScript، لكن بعض محركات البحث ومعاينات الشبكات الاجتماعية قد لا تنفذ JavaScript.

## من الصفر إلى موقع منشور

1. أنشئ حساب GitHub وفعّل البريد الإلكتروني إذا لم يكن لديك حساب. لا ترسل كلمة المرور أو token لأي شخص.
2. أنشئ مستودعًا **Public** إذا كنت تستخدم GitHub Free للمسار البسيط.
3. لديك خياران للاسم:
   - `USERNAME.github.io` → الموقع يكون `https://USERNAME.github.io/`
   - أي اسم مثل `book-review` → الموقع يكون `https://USERNAME.github.io/book-review/`
4. فك `github-pages-book-review.zip` على جهازك. **ارفع محتويات ZIP وليس ملف ZIP نفسه**.
5. في المستودع: **Add file → Upload files**. ارفع الملفات مع الحفاظ على المجلدات. يجب أن يكون `index.html` في جذر المستودع مباشرة، وليس داخل مجلد إضافي.
6. تأكد أن `.nojekyll` موجود في الجذر. إذا فُقد، أنشئ ملفًا جديدًا بهذا الاسم واتركه فارغًا.
7. افتح **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: main → Folder: /(root) → Save**.
8. انتظر اكتمال النشر ثم افتح الرابط الحقيقي الذي يعرضه GitHub داخل صفحة Pages. لا تفترض أن النشر فوري.
9. عد إلى `data/site.json` وضع `site_url` الصحيح، وضع `github_url` إن أردت إظهار زر GitHub.

المراجع الرسمية: [إنشاء موقع GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)، [اختيار مصدر النشر](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)، [رفع الملفات من المتصفح](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository).

### ملاحظات مهمة للنشر

- GitHub Pages يستطيع النشر من فرع ومجلد الجذر، ولا تحتاج ملف GitHub Actions مخصص لهذا المشروع.
- قد ترى تشغيل Pages داخل تبويب Actions؛ هذا طبيعي حتى عند اختيار **Deploy from a branch**.
- مع GitHub Free، المسار الأبسط هو مستودع عام.
- فتح `index.html` بالنقر المزدوج عبر `file://` ليس معاينة مدعومة لأن ES modules وJSON يحتاجان HTTP(S). استخدم GitHub Pages كمعاينة عادية.

## أربع عمليات يومية

### إضافة كتاب جديد بأقل عدد من الخطوات

1. ارفع الغلاف أولًا إلى `assets/covers/`.
2. افتح أداة الصيانة المنشورة، حمّل أحدث `books.json` و`updates.json`، أضف الكتاب، وأضف حدث `release` الأول عند نشر أول PDF حقيقي.
3. تحقق ثم نزّل **الملفين**.
4. في GitHub: `data → Add file → Upload files` وارفع `books.json` و`updates.json` معًا، راجع الفرق ثم Commit.

التفاصيل والقالب الجاهز: [`HOW_TO_ADD_A_BOOK.md`](HOW_TO_ADD_A_BOOK.md).

### نشر تحديث جديد لكتاب موجود

1. إذا كان لديك PDF جديد، احتفظ بالملف القديم في Drive ولا تستبدل التاريخ بصمت.
2. سجّل الرابط القديم في حدث الإصدار التاريخي إذا لم يكن مسجلًا.
3. ارفع PDF الجديد كملف جديد في Drive واضبط مشاركته.
4. حدّث `books.json` بالإصدار والرابط والحالة/التقدم الحالية، وأضف حدثًا جديدًا في بداية `updates.json`.
5. نزّل الملفين وارفعهما معًا إلى `data/` ثم Commit.

التفاصيل: [`HOW_TO_UPDATE_A_BOOK.md`](HOW_TO_UPDATE_A_BOOK.md).

### تصحيح بيانات فقط بلا إصدار جديد

- غيّر الحقل المطلوب في `books.json` مثل الوصف أو الغلاف أو الرابط المصحح.
- عدّل `last_updated` لأنه تغيير مباشر في سجل الكتاب.
- لا تضف حدثًا تاريخيًا إلا إذا كان للتغيير قيمة تستحق التسجيل.
- تصحيح رابط كتبته خطأ لا ينبغي أن يجعل حدثًا قديمًا يشير إلى ملف مختلف عن الإصدار الذي كان يقصده.

### ماذا أفعل عندما أنتهي من جولة مراجعة PDF على Google Drive؟

1. اترك ملف الجولة القديمة مع تعليقاتها ولا تحذفه أو تستبدله.
2. راجع الملاحظات وعدّل المصدر القابل للتحرير.
3. أنشئ PDF جديدًا باسم إصداري مثل `book-id_review_v1.1.pdf` وارفعه كملف جديد.
4. اضبط مشاركة الملف الجديد وحده، ثم حدّث `books.json` بالرابط الحالي وأضف `release` جديدًا في `updates.json`.
5. أبقِ رابط الإصدار السابق داخل حدثه التاريخي، واحتفظ بنسخ محلية من المصدر وPDF.

هذا مسار تنظيمي موصى به، وليس ضمانًا من Google لنقل التعليقات. انظر [`GOOGLE_DRIVE_SETUP.md`](GOOGLE_DRIVE_SETUP.md).

## قاعدة الإصدارات

- `v1.1`، `v1.2`…: تصحيحات وتحسينات تدريجية.
- `v2.0`: إصدار مراجعة/ترجمة أعيدت صياغته بشكل كبير.
- بداية جولة مراجعة جديدة **لا تعني تلقائيًا** قفزة major.

أمثلة معرفات دائمة جيدة: `serway-physics-9`، `cheng-field-wave-2`، `language-learning-notes`. المعرف ليس عنوان العرض، ولا تغيّره عند تغيير اسم الكتاب.

## النسخ الاحتياطي والاسترجاع

قبل تغيير كبير استخدم **Code → Download ZIP** لأخذ نسخة من مصدر الموقع. هذا لا ينسخ ملفات Drive أو تعليقاتها؛ احتفظ بنسخ منفصلة من المصادر القابلة للتحرير وPDF المنشور.

لاسترجاع ملف واحد فقط بدون مسح عمل آخر:
1. افتح الملف على GitHub.
2. اختر **History**.
3. افتح commit معروفًا بأنه سليم.
4. افتح **Raw** وانسخ المحتوى القديم.
5. ارجع إلى نسخة الملف الحالية على فرع `main`.
6. اختر **Edit**، استبدل محتوى هذا الملف فقط، ثم **Commit changes**.

## المشاركة والمعاينات الاجتماعية

الموقع يرسل معاينة عامة للمشروع فقط. صفحة `book.html?id=...` تعتمد على JavaScript، وبعض crawlers لا تنفذه، لذلك لا يمكن ضمان عنوان/صورة اجتماعية مختلفة لكل كتاب من دون نظام بناء أو صفحات ثابتة منفصلة. هذا المشروع يتعمد تجنب backend والبناء الآلي للحفاظ على البساطة.
